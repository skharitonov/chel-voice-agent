# Голосовой AI-агент (AI SDR) для ЧЗЭ

Прототип голосового AI-агента холодного обзвона для Челябинского завода
электротехники (ЧЗЭ). Два сценария: **A — квалификация лида**, **B — поиск ЛПР по
методу Соколова**.

> **Это эксперимент, не production.** Цель — проверить, реально ли заменить/дополнить
> живого обзвонщика AI-агентом при тестовом бюджете $10–20.

📄 [PRD](docs/specs/2026-06-10-voice-agent.md) · 🏗 [Архитектура](ARCHITECTURE.md) ·
🔬 [Ресёрч платформ](docs/research/) · 📋 [Исходная задача](TASK.md)

## Выбор платформы

**Архитектура: STT → LLM → TTS на LiveKit** (не end-to-end мультимодальная модель).

Решение опирается на [исследование](docs/research/) двух Telegram-каналов и анализ
4 референсных проектов курса AI Product Engineer. Оба источника независимо сходятся:
для длинных cold-call сценариев конвейер STT→LLM→TTS даёт **контроль контекста** и
**постобработку транскрипта**, тогда как end-to-end модели теряют контекст после
5–7 минут. Для метода Соколова это критично — нужно точно фиксировать, что сказал
секретарь (ФИО, цифры номера).

### Итоговый стек

| Слой | Выбор | Цена | Почему |
|------|-------|------|--------|
| Оркестрация | LiveKit Agents SDK (Python) | — | Готовый код из лекции; стек всех 4 референсов |
| STT | Deepgram Nova-2 (или Whisper локально) | ~$0.0043/мин | Русский, низкая задержка |
| LLM реплик | Claude Sonnet 4.6 | по токенам | «Режиссура» диалога, сильное рассуждение |
| LLM постобработки | Claude Haiku 4.5 | по токенам | Дешёвое извлечение JSON, комплаенс-проверки |
| TTS | Inworld TTS 1.5 Mini | $0.005/мин | Русский, Voice Direction, топ арены |
| Телефония (фаза 3) | Twilio SIP → +7 | — | Контроль; вне scope прототипа |

**Оценка стоимости звонка (~3 мин голосом): ~$0.05–0.07** — в пределах целевых
< $0.10. Текстовая симуляция (фаза 1) стоит центы (только токены LLM).

## Что не сработало и почему

Платформы и подходы, которые рассмотрели и **отклонили**:

| Вариант | Почему отклонён |
|---------|-----------------|
| **End-to-end Gemini Flash Live** | Дёшево ($0.02–0.03/мин) и русский из коробки, но теряет контекст на разговорах > 5–7 мин и начинает повторяться. Нет постобработки транскрипта — плохо для длинных звонков и точного отслеживания реплик секретаря. Оставлен как опциональный TTS-fallback, не как ядро. |
| **Vapi / Bland / Retell** | Полностековые решения с готовой телефонией, но **нет верифицированного качества на русском** (в ресёрче явно отмечено «не протестировано на RU»), и проблемы с исходящими на +7. |
| **Cartesia Sonic 3.5** | Топ TTS-арены на английском, но на русском — «не очень эмоциональная и с проблемами с ударениями». Не годится для русскоязычного агента. |
| **Twilio для исходящих на +7** | Хороший контроль, но русские исходящие через Twilio дороги/проблемны (caller ID, блокировки). Для фазы 3 ближе российский SIP (Zadarma / Novofon / MTS Exolve). |
| **Grok Voice / OpenAI Realtime end-to-end** | Качество хорошее, но это снова end-to-end (потеря контекста) и/или премиум-цена ($0.05/мин). Конвейер STT→LLM→TTS даёт больше контроля дешевле. |

Подробные таблицы цен и качества — в
[`docs/research/voice-platforms-russian.md`](docs/research/voice-platforms-russian.md).

## Архитектура (кратко)

Один голосовой агент + 4 супервайзера вокруг общего состояния:

- **DialogueDirector** — «режиссёр»: стадии разговора и переключение тактик (эскалация Соколов M1→M2→M3).
- **ObjectionHandler** — ответы на «кто звонит?», «по какому вопросу?», прерывания.
- **ComplianceGuard** — проверка реплик: без прямой лжи, стоп-слова, корректный выход по отказу.
- **JSONExtractor + Reporter** — структурированный результат + отчёт менеджеру (human-in-the-loop).

Полная схема — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

> ⚠️ Фаза 1 (текстовая симуляция) — рабочий прототип. Фаза 2 (голос) подключается
> теми же модулями. Реальная телефония (+7) — вне scope прототипа.

### 1. Установка

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 2. Ключи

```bash
copy .env.example .env          # затем заполнить ключи
```

**LLM-бэкенд** выбирается переменной `LLM_BACKEND`:
- `openrouter` — единый OpenAI-совместимый шлюз; ключ `OPENROUTER_API_KEY`, слаги
  моделей в формате `anthropic/claude-sonnet-4.6` (см. openrouter.ai/models).
- `anthropic` — прямой Anthropic API; ключ `ANTHROPIC_API_KEY`.

Смена бэкенда не затрагивает логику диалога — провайдер за интерфейсом
(`voice_agent/providers.py`, фабрика `make_llm()`). Для фазы 2 (голос) дополнительно
нужны `DEEPGRAM_API_KEY`, `INWORLD_API_KEY`, `LIVEKIT_URL/API_KEY/API_SECRET`.

### 3. Текстовая симуляция (фаза 1)

```bash
# Сценарий A — квалификация
python scripts/qualify.py --phone "+7XXXXXXXXXX" --company "Рудник Северный" --mode A

# Сценарий B — поиск ЛПР
python scripts/find_lpr.py --phone "+7XXXXXXXXXX" --role "главный энергетик" --mode B
```

Результат: JSON в `results/<timestamp>_<mode>.json` + лог транскрипта.

### 4. Голос локально — фаза 2 (LiveKit console)

Голосовое ядро на LiveKit Agents: вы говорите за секретаря/ЛПР, агент-завод
отвечает синтезированной речью. Микрофон → Deepgram STT → наш конвейер → Inworld
TTS → динамики. Локально, без сервера LiveKit и без телефонии.

```bash
pip install -r requirements.txt   # подтянет livekit-agents и плагины
# в .env: DEEPGRAM_API_KEY, INWORLD_API_KEY (base64), CHEL_MODE/PHONE/COMPANY
python scripts/test_voice.py       # пре-флайт: проверка ключей Deepgram + Inworld
python -m voice_agent.voice_core console
```

Ctrl+C завершает звонок → тот же extractor пишет JSON+транскрипт в `results/`.
Параметры голоса и звонка — через переменные `.env` (см. `.env.example`).

## Этика

Сценарий B использует техники прохода блокера (pretexting). Прототип — **внутренний
инструмент авторизованного B2B-обзвона ЧЗЭ**. Принцип из первоисточника:
**эвазия, а не прямая ложь** — агент не представляется, но не утверждает ложных
фактов. Это контролирует `ComplianceGuard`. Подробнее — [PRD §6](docs/specs/2026-06-10-voice-agent.md).
