## 1. Проблема и гипотеза

**Контекст.** Челябинский завод электротехники (ЧЗЭ) производит взрывозащищённые
трансформаторные подстанции (КТПВШ, КТПВМ, КТПРН) для шахт, рудников и ГОКов.
Продажи — B2B, высокий средний чек, длинный цикл сделки. Лиды берутся из открытых
источников (Яндекс Карты, 2GIS, Контур.Компас); целевые ЛПР — **главные
энергетики** и **главные инженеры** горнодобывающих предприятий.

**Боль.** Первичный холодный обзвон (квалификация + поиск ЛПР) выполняется живыми
обзвонщиками — это дорого, медленно и плохо масштабируется. Большая часть звонков
не доходит до ЛПР: блокирует секретарь/приёмная.

**Гипотеза.** Голосовой AI-агент способен заменить или дополнить живого
обзвонщика на этапе первичного контакта (квалификация и выход на ЛПР) при тестовом
бюджете **$10–20**, сохраняя приемлемое качество русской речи и стоимость
**< $0.10 за звонок**.

**Что проверяем прототипом.** Реалистичность сценария end-to-end: агент держит
легенду, обрабатывает возражения секретаря, применяет тактики, отдаёт
структурированный результат менеджеру. Прототип — **эксперимент, не production**.

## 2. Пользователи

| Роль | Кто | Как использует |
|------|-----|----------------|
| **Оператор кампании** | Менеджер по продажам ЧЗЭ | Запускает обзвон по списку номеров, читает отчёты, решает кого передавать в работу |
| **ЛПР (цель)** | Главный энергетик / главный инженер ГОКа | Конечный объект сценария A (косвенно), сценария B (находим контакт) |
| **Блокер** | Секретарь / сотрудник приёмной | Первый контакт; объект тактик прохода |

**Human-in-the-loop обязателен** (вывод из ресёрча): агент только квалифицирует и
собирает данные → формирует отчёт → **решение о передаче лида принимает человек**.

## 3. Сценарии

### Сценарий A — Квалификация лида (Lead Qualification)

**Вход:** номер телефона компании + название компании.

**Легенда:** звонок от «партнёрской компании», готовящей технический обзор рынка
подземного электрооборудования. Не продажа — сбор информации.

**Цель — выяснить:**
1. Есть ли на предприятии КТПВШ/КТПВМ/трансформаторные подстанции?
2. Кто ответственный — ФИО главного энергетика / главного инженера?
3. Когда последний раз меняли подстанции, есть ли план на ближайший год?

**Выход — JSON:**
```json
{
  "company": "...",
  "phone": "...",
  "qualified": true,
  "lpr_name": "...",
  "lpr_contact": "...",
  "notes": "..."
}
```

### Сценарий B — Поиск ЛПР по методу Соколова (LPR Finder)

**Вход:** номер телефона компании (общий/приёмная) + должность нужного ЛПР
(например, «главный энергетик»).

**Цель:** получить ФИО и прямой номер ЛПР у секретаря / другого сотрудника.

**Техники** (источник: `chel-main/02-research/telegram/sales/lpr-methods.md`,
методы 1–3 и общие принципы прохода блокера, п. 9):

- **Метод 1 «Пишу письмо»:** открытие без представления → «напомните отчество
  вашего главного энергетика?» → получив ФИО, назвать выдуманный номер-якорь
  («…номер не менялся? 9XX-XXX-XX-XX?») → секретарь рефлекторно исправляет →
  записать реальный номер.
- **Метод 2 «Добавочный → мобильный»:** запросить добавочный через якорь; если
  добавочного нет — эскалация на личный мобильный; при «в командировке» — выбить
  последние 2 цифры.
- **Метод 3 «Через другой отдел»:** при сопротивлении — заход через бухгалтерию/
  склад/IT; на встречные вопросы — односложные ответы, сразу возврат инициативы.

**Выход — JSON:**
```json
{
  "company": "...",
  "phone": "...",
  "target_role": "главный энергетик",
  "lpr_name": "...",
  "lpr_mobile": "...",
  "method_used": "1|2|3",
  "notes": "..."
}
```

## 4. Функциональные требования

| # | Требование |
|---|-----------|
| F1 | Принять номер телефона как аргумент командной строки |
| F2 | Выбрать сценарий флагом `--mode A` / `--mode B` |
| F3 | Провести разговор по скрипту выбранного сценария |
| F4 | Обрабатывать прерывания и встречные вопросы: «кто звонит?», «по какому вопросу?», «откуда у вас номер?» |
| F5 | Переключать тактику по ходу диалога (стадии A; эскалация Соколов M1→M2→M3) |
| F6 | Извлекать структурированный результат (Pydantic) и писать JSON в `results/` |
| F7 | Логировать полный транскрипт звонка |
| F8 | Формировать краткий отчёт менеджеру (human-in-the-loop) |
| F9 | Корректно завершать разговор по запросу «не звоните больше» / отказу |

## 5. Нефункциональные требования

| # | Требование | Цель |
|---|-----------|------|
| N1 | Стоимость теста | < **$0.10** за звонок; общий бюджет $10–20 |
| N2 | Качество русской речи | Естественное произношение, корректные термины (КТПВШ, отчества) |
| N3 | Задержка отклика | Комфортная для телефонного разговора (целевая < 1.5 c на реплику в голосовой фазе) |
| N4 | Контроль контекста | Архитектура STT→LLM→TTS — управляемая память, постобработка транскрипта |
| N5 | Заменяемость провайдеров | STT/LLM/TTS за интерфейсами — можно менять без правки логики |
| N6 | Воспроизводимость | Промпты как версионируемые md-файлы; секреты в `.env` (не в коде) |

## 6. Этические и комплаенс-рамки

Сценарий B использует техники социальной инженерии (pretexting). Рамки прототипа,
вытекающие из самого первоисточника (lpr-methods.md, п. 9 «Ключевой принцип»):

- **Внутренний инструмент** авторизованного B2B-обзвона ЧЗЭ, не публичный сервис.
- **Эвазия, а не прямая ложь.** Агент не представляется, но не утверждает ложных
  фактов («я ваш поставщик», «мы уже работаем») — это прямо помечено ❌ в источнике.
- **ComplianceGuard** проверяет каждую исходящую реплику: запрет прямой лжи,
  стоп-слова, корректный выход по «не звоните больше» / явному отказу.
- Выдуманный номер-якорь допустим как тактика проверки данных (он не выдаётся за
  факт о третьем лице, а провоцирует исправление) — но guard следит, чтобы агент
  не приписывал ложные данные конкретным людям.

## 7. Метрики успеха прототипа

| Метрика | Цель прототипа |
|---------|----------------|
| Доля звонков с валидным JSON-выходом | 100% (структурный) |
| Доля смоделированных диалогов, где агент держит легенду без срыва | ≥ 80% |
| Корректная обработка встречных вопросов | ≥ 80% диалогов |
| Стоимость на звонок | < $0.10 |
| Срабатывание guard на запрещённые реплики | 100% запрещённых блокируются |

Тестирование — по «философии autoresearcher» (onsa.ai): агент-секретарь на второй
LLM, без реальных людей, до выхода на приемлемые параметры.

## 9. Вне scope

- Реальные исходящие звонки на номера +7 (фаза 3, отдельная задача).
- Поиск/скрапинг базы телефонов (методы 4–8 Соколова — ОСИНТ без звонка).
- Интеграция с CRM, дозвонщик по списку, аналитика кампаний.
- Дообучение собственных TTS/STT-моделей.
- Полная мультиагентная оркестрация всего пайплайна продаж (выбран узкий scope:
  один голос + супервайзеры).

## 10. Открытые вопросы

- Источник реального русского caller ID для +7 (фаза 3): российский SIP-провайдер
  (Zadarma / Novofon / MTS Exolve) — требует отдельной проверки на блокировки.
- Юридическая допустимость записи разговоров и pretexting в РФ для холодного
  обзвона — уточнить с юристом ЧЗЭ перед фазой 3.
