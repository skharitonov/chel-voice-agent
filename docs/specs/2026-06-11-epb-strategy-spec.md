## 1. Зачем (контекст для исполнителя)

Текущий сценарий A провалился по замыслу: бот задаёт вопрос про трансформаторные
подстанции первому, кто поднял трубку (секретарю), под легендой «технический
обзор рынка». Секретарь не знает ответа и отшивает как продавца.

Новая стратегия (по структуре книги продаж ККП «Эврика Би Пи О», адаптация — в
скрипте-первоисточнике):

1. **Секретарь — не объект квалификации.** Его единственная функция — соединить
   с ЛПР или отдать его контакты. Никаких вопросов про парк подстанций секретарю
   (исключение — один бинарный фильтр в УКС-7).
2. **Легенда — честная и надзорно-техническая:** бот представляется ЧЗЭ
   (завод-производитель) и звонит «по вопросу подстанций с истекающим
   нормативным сроком службы» (ЭПБ по 116-ФЗ, срок 25 лет по ГОСТ 14695-80).
   Легенда «партнёрской компании с техобзором» — **удаляется**.
3. **16 детерминированных обработчиков возражений секретаря (УКС-1…16)** —
   каждый тупик конвертируется в данные (ФИО/почта/добавочный/дата перезвона).
4. **Квалификация — только с ЛПР**, 5 вопросов по схеме
   «вопрос → выслушать → мини-ценность».

Все формулировки реплик — в [`2026-06-11-epb-call-script.md`](2026-06-11-epb-call-script.md).
Этот spec описывает, **что поменять в коде и промптах**.

## 2. Объём изменений по файлам

### 2.1 `prompts/qualify_system.md` — ПЕРЕПИСАТЬ
- Удалить легенду «партнёрская компания / техобзор рынка».
- Новая личность: сотрудник ЧЗЭ (Челябинский завод электрооборудования),
  производителя КТПВШ/КТПВМ/КТПРН. Представляется честно.
- Две фазы разговора (см. §2.4 — стадии Director):
  - **фаза «секретарь»**: цель — соединение с ЛПР; жёсткий запрет на
    квалификационные вопросы и любые рассказы о продукте; реплики коротки,
    каждая заканчивается «переключите, пожалуйста» или вопросом;
  - **фаза «ЛПР»**: вход + 5 квалификационных вопросов + wrap (из скрипта §5).
- Сохранить существующие правила речи (короткие реплики, формат вывода —
  только озвучиваемая реплика).

### 2.2 `prompts/shared/objections.md` — ЗАМЕНИТЬ содержимое
- Вместо текущей таблицы из 8 строк — 16 обработчиков УКС-1…16 из скрипта §4.
- Формат: для каждого УКС — паттерны распознавания (фразы секретаря) +
  реплика(и) агента + обязательный «выход ветки» (что извлечь, если соединение
  не состоялось).
- Сохранить раздел «Жёсткие границы» и дополнить его (см. §2.5).

### 2.3 `voice_agent/objections.py` — ОБНОВИТЬ
- Классификатор возражений: расширить таблицу паттерн→тип до 16 типов УКС
  (сейчас ~8 типов под метод Соколова).
- Каждому типу — подсказка-директива для main LLM (короткая, 1–2 предложения,
  со ссылкой на целевую реплику из промпта).
- Тип возражения логировать в state (`uks_triggered: list[str]`) — нужен в
  итоговом JSON.

### 2.4 `voice_agent/director.py` — ОБНОВИТЬ стадии сценария A
Новая карта стадий:

```
gatekeeper_intro      открытие секретарю (скрипт §3)
gatekeeper_objection  цикл обработки УКС (повторяемый; счётчик попыток)
gatekeeper_extract    тупик: извлечение данных (ФИО/почта/добавочный/перезвон)
lpr_intro             вход к ЛПР (скрипт §5.1)
lpr_qualify_1..5      пять вопросов (скрипт §5.2); продвижение по получении ответа
lpr_wrap              следующий шаг + завершение (скрипт §5.3)
wrap                  финальное вежливое завершение (любая фаза)
```

Правила переходов:
- `gatekeeper_objection`: максимум **3 круга** возражений; после третьего —
  принудительный переход в `gatekeeper_extract` (не зацикливаться).
- Переход `gatekeeper_* → lpr_intro` — по сигналу «соединяю» / смене собеседника
  (детект: новое приветствие, смена манеры; в текстовой симуляции — явная метка).
- `УКС-7 бинарный фильтр`: ответ «нет подземной добычи» → сразу `wrap`,
  `qualified=false`.
- Из любой стадии по «не звоните больше» → `wrap` (существующее поведение
  ComplianceGuard сохраняется).
- Director обязан перед `wrap` проверить «Правило №1» скрипта: если ни одно
  поле данных не заполнено и разговор не отказной — директива LLM на последнюю
  попытку извлечения (почта/ФИО/дата перезвона).

### 2.5 `voice_agent/compliance.py` + `prompts/shared/compliance.md` — ДОПОЛНИТЬ
Новые детерминированные запреты (прямая ложь, исключённая при адаптации книги):
- утверждения о несуществующих договорённостях: «мы договаривались»,
  «он ждёт моего звонка», «мы уже общались», «вы оставляли заявку»;
- утверждения о предписаниях/проверках: «у вас предписание», «к вам придёт
  проверка», «Ростехнадзор вас оштрафует»;
- утверждения о состоянии чужого парка: «ваши подстанции просрочены»
  (допустимо только условно: «если есть подстанции старше 25 лет…»).

Разрешённые фактические утверждения (whitelist для guard, чтобы не было ложных
блокировок): ссылки на 116-ФЗ ст. 7, ГОСТ 14695-80 и срок 25 лет, общее
требование ЭПБ.

### 2.6 `voice_agent/state.py` — РАСШИРИТЬ `QualifyResult`
Привести модель к JSON-схеме из скрипта §6:
`outcome`, `binary_filter`, `lpr_name`, `lpr_role`, `lpr_email`,
`lpr_phone_ext`, `park{total, types, expired_or_on_epb, last_replacement_year}`,
`purchase{plan, channel}`, `decision_chain`, `callback_at`, `secretary_name`,
`uks_triggered`, `notes`. Поля опциональные, `outcome` — обязательное
(enum: `connected_lpr | data_extracted | callback_scheduled | not_qualified | refused`).

### 2.7 `voice_agent/extractor.py` — ОБНОВИТЬ
- Промпт экстрактора: извлекать новую схему из транскрипта.
- Reporter: в отчёте менеджеру выделять «горячие» признаки
  (`expired_or_on_epb > 0`, назначенный следующий шаг).

### 2.8 `scripts/qualify.py` — БЕЗ ИЗМЕНЕНИЙ интерфейса
Опционально: флаг `--lpr-name "Имя Отчество"` — если ФИО известно из ОСИНТ,
открытие становится адресным (скрипт §3, замечание 2).

### 2.9 Сценарий B (`find_lpr_*`) — НЕ ТРОГАТЬ

## 3. Тестирование (фаза 1, текстовая симуляция)

Через `text_sim.py` с LLM-секретарём (подход autoresearcher, PRD §7). Персоны
секретаря — минимум 6 прогонов:

| # | Персона секретаря | Ожидаемый исход |
|---|---|---|
| 1 | Дружелюбный, сразу соединяет | `connected_lpr`, дошли до `lpr_wrap`, JSON полон |
| 2 | Фильтр: «по какому вопросу?» ×2, потом соединяет | УКС-1/УКС-16 отработаны, соединение |
| 3 | «Пришлите на почту», имя не называет | `data_extracted`: почта + ФИО (через приём «спам») или почта + дата перезвона |
| 4 | «Нам ничего не нужно», подземной добычи нет | `not_qualified`, бинарный фильтр сработал, разговор < 1 мин |
| 5 | «Запрещено соединять», жёсткий | `data_extracted` или `callback_scheduled`, без нарушений compliance |
| 6 | ЛПР: «у нас всё новое» | `not_qualified` (отложен), `callback_at` заполнен, год последней замены записан |

Критерии приёмки:
1. Все 6 прогонов дают валидный JSON с непустым `outcome` (Правило №1).
2. ComplianceGuard блокирует тестовые реплики с фабрикациями из §2.5
   (юнит-тест на список запрещённых фраз) — 100%.
3. В фазе «секретарь» агент ни разу не задаёт вопросов про парк/типы
   подстанций (кроме бинарного фильтра в УКС-7) — проверка по транскриптам.
4. После 3 кругов возражений агент уходит в извлечение данных, не зацикливается.
5. Прогоны 1–2: в блоке ЛПР заданы все 5 вопросов, каждый с ожиданием ответа
   (нет «анкетных» монологов из 2+ вопросов в одной реплике).

## 4. Вне scope этого spec

- Голосовая фаза (фаза 2) и телефония (фаза 3) — без изменений, по PRD.
- ОСИНТ-подготовка (ФИО энергетика до звонка) — отдельный процесс; spec лишь
  принимает `--lpr-name` как вход.
- Предзвонковая фильтрация базы (отрасль/ОКВЭД/тендерная история) — вне
  кода агента; выполняется при формировании списка обзвона.

## 5. Порядок работ (рекомендуемый)

1. `state.py` (новая модель результата) → 2. `prompts/shared/objections.md` +
`objections.py` (16 УКС) → 3. `prompts/qualify_system.md` (две фазы) →
4. `director.py` (стадии/переходы) → 5. `compliance.py` (+ промпт) →
6. `extractor.py` → 7. персоны секретаря для `text_sim.py` и прогон тестов §3.

На каждом шаге сверяться с формулировками скрипта-первоисточника — реплики из
него переносить в промпты дословно (это согласованный с заказчиком текст).
