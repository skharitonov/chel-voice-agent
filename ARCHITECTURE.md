## 1. Ключевое архитектурное решение

**STT → LLM → TTS, а НЕ end-to-end мультимодальная модель.**

Оба источника ресёрча ([`voice-architecture-insights.md`](docs/research/voice-architecture-insights.md),
[`voice-platforms-russian.md`](docs/research/voice-platforms-russian.md)) сходятся:
для длинных cold-call сценариев конвейер STT→LLM→TTS предпочтительнее end-to-end
(GPT-4o Voice, Gemini Live), потому что:

- end-to-end теряет контекст на разговорах > 5–7 минут и начинает повторяться;
- конвейер даёт **постобработку транскрипта** — можно «срезать» лишнее перед подачей в LLM;
- **контроль контекста** — критично для метода Соколова: нужно точно отслеживать,
  что именно сказал секретарь (ФИО, цифры номера).

Главная задача агента — не идеально имитировать голос, а **«режиссировать» диалог**:
управлять темпом и инициативой. Это реализует супервайзер `DialogueDirector`.

## 2. Состав системы: 1 голосовой агент + 4 супервайзера

```
                         ┌──────────────────────────────────────────┐
                         │            ConversationState              │
                         │  (Pydantic: стадия, тактика, транскрипт,  │
                         │   собранные факты, флаги завершения)       │
                         └──────────────────────────────────────────┘
                                  ▲ читают/пишут все модули

   Входящее аудио/текст
        │
        ▼
   ┌─────────┐   transcript   ┌──────────────────┐  директива тактики
   │   STT   │ ─────────────► │ DialogueDirector │ ───────────────┐
   └─────────┘                │  (стадии/тактики, │                │
   (Deepgram/                 │   эскалация M1→M3)│                ▼
    Whisper)                  └──────────────────┘        ┌─────────────────┐
                                                          │   main LLM      │
   ┌──────────────────┐  встроена в системный промпт ───► │  (Claude Sonnet)│
   │ ObjectionHandler │  «кто звонит?», «по какому…»      │   генерит реплику│
   └──────────────────┘                                   └─────────────────┘
                                                                   │ реплика
                                                                   ▼
                                                          ┌─────────────────┐
                                                          │ ComplianceGuard │
                                                          │ (правила+Haiku):│
                                                          │ нет лжи,стоп-слова│
                                                          └─────────────────┘
                                                            │ ok        │ block
                                                            ▼           └─► регенерация/
   ┌─────────┐   аудио                                  ┌─────────┐         санитизация
   │   TTS   │ ◄───────────────────────────────────────│ реплика │
   └─────────┘                                          └─────────┘
   (Inworld 1.5 Mini)

   ─────────────── ПОСТ-ОБРАБОТКА (после завершения разговора) ───────────────
   полный транскрипт ─► JSONExtractor (Haiku) ─► Pydantic-результат
                                              ─► Reporter ─► отчёт менеджеру
                                              ─► results/<ts>_<mode>.json + transcript.log
```

В **фазе 1 (текст)** STT и TTS отключены: ввод/вывод идёт через терминал, весь
остальной конвейер (Director → LLM → Guard → Extractor) работает без изменений.

## 3. Компоненты

### 3.1 Голосовое ядро — `voice_agent/voice_core.py` + `voice_agent/lk_llm.py` (фаза 2) ✅
- Хост на **LiveKit Agents SDK 1.5** (`AgentSession`): VAD/перебивание, локальный
  `console`-режим (микрофон/динамик), без сервера LiveKit.
- Плагины: **Deepgram** STT (Nova-3 multilingual), **Inworld** TTS (офиц. плагин),
  **Silero** VAD.
- `lk_llm.ChelLLM` — адаптер: оборачивает наш текстовый конвейер
  (`pipeline.generate_reply`: Director → LLM → Guard) как `llm.LLM`, поэтому вся
  режиссура/УКС/комплаенс работают в голосе **без изменений**. Источник правды —
  тот же `ConversationState`; на завершении звонка — тот же `extractor`.
- Запуск: `python -m voice_agent.voice_core console`.

### 3.2 Текстовая симуляция — `voice_agent/text_sim.py` (фаза 1)
- Тот же конвейер без аудио. Реплики пользователя/секретаря — из stdin или из
  второй LLM (агент-секретарь для автотестов, «autoresearcher»-подход onsa.ai).

### 3.3 DialogueDirector — `voice_agent/director.py`
- Хранит и продвигает **стадии** разговора:
  - Сценарий A: `intro → probe_substations → probe_responsible → probe_timeline → wrap`.
  - Сценарий B: `intro(M1: имя) → anchor(M1: номер) → escalate(M2: добавочный→мобильный) → detour(M3: другой отдел) → wrap`.
- Решает переключение тактики (например, эскалация при «добавочного нет»).
- Возвращает **директиву** — короткую инструкцию, инжектируемую в контекст main LLM.

### 3.4 ObjectionHandler — `voice_agent/objections.py`
- Тактики ответов на встречные вопросы блокера («кто звонит?», «по какому
  вопросу?», «откуда номер?», «пришлите на почту»).
- Реализован как секция системного промпта + таблица паттерн→реакция; модуль
  подбирает подсказку по распознанному типу возражения.

### 3.5 ComplianceGuard — `voice_agent/compliance.py`
- Проверяет каждую исходящую реплику **до** TTS:
  - детерминированные правила: стоп-слова, запрет прямых ложных утверждений
    («я ваш поставщик», «мы уже работаем»), маркеры отказа собеседника;
  - быстрая проверка через Haiku для пограничных случаев.
- При блокировке — регенерация реплики или безопасная санитизация; при отказе
  собеседника («не звоните больше») — установка флага завершения в state.

### 3.6 JSONExtractor + Reporter — `voice_agent/extractor.py`
- После разговора прогоняет полный транскрипт через Haiku, извлекает Pydantic-модель
  результата (`QualifyResult` / `LprResult`).
- Reporter формирует краткий отчёт менеджеру (human-in-the-loop).
- Пишет `results/<timestamp>_<mode>.json` и лог транскрипта.

### 3.7 Состояние — `voice_agent/state.py`
- `ConversationState`: режим (A/B), вход (телефон, компания, целевая роль), текущая
  стадия и тактика, накопленный транскрипт, собранные факты, флаги завершения/отказа.
- Pydantic-модели результатов: `QualifyResult`, `LprResult` (схемы из PRD §3).

### 3.8 Провайдеры — `voice_agent/providers.py`
- Интерфейсы `STTProvider`, `LLMProvider`, `TTSProvider` + конкретные реализации.
- Точки замены без изменения логики (требование N5).

## 4. Стек и точки замены

| Слой | По умолчанию | Альтернатива | Интерфейс |
|------|--------------|--------------|-----------|
| Оркестрация | LiveKit Agents SDK 1.5 (Python) | — | — |
| STT | Deepgram Nova-3 (multilingual) | Whisper large-v3 (локально) | плагин LiveKit |
| LLM реплик | Claude Sonnet 4.6 (через `make_llm()`/OpenRouter) | GPT-4o mini | `LLMProvider` + `lk_llm.ChelLLM` |
| LLM постобработки | Claude Haiku 4.5 | — | `LLMProvider` |
| TTS | Inworld TTS (офиц. плагин LiveKit) | ElevenLabs, Gemini Flash Live | плагин LiveKit |
| Телефония (фаза 3) | Twilio SIP → LiveKit SIP | Zadarma / Novofon / MTS Exolve (RU) | — |

**Почему Inworld TTS 1.5 Mini:** русский, $0.005/мин, низкая задержка, **Voice
Direction** (режиссёрские ремарки в скобках) — прямо ложится на «режиссуру диалога».

---

## 5. Поток данных по фазам

- **Фаза 0 (каркас):** `state.py`, `providers.py` (интерфейсы), промпты, конфиг.
- **Фаза 1 (текст):** `text_sim.py` + Director + ObjectionHandler + Guard + Extractor.
  Запуск через `scripts/qualify.py` / `scripts/find_lpr.py`. Это рабочий прототип.
- **Фаза 2 (голос):** ✅ реализована — `voice_core.py` + `lk_llm.py` на LiveKit
  Agents, локальный `console` (Deepgram STT + Inworld TTS + Silero VAD). Тот же
  конвейер и тот же extractor, что в фазе 1. Нужны ключи `DEEPGRAM_API_KEY`,
  `INWORLD_API_KEY` (base64).
- **Фаза 3 (телефония, вне scope):** SIP-мост к Twilio/RU-провайдеру.
